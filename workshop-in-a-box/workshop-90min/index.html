📦 Workshop-in-a-BoxRun a Workshop

Run a Workshop

Use this page to run a standalone sandbox workshop. Use it as the main guide for a 90-minute or longer session.

A 75-90 minute format gives facilitators enough time to move from shared experience to individual design:

  • frame the sandbox as a structure for educator judgment
  • let participants explore a prepared sandbox together
  • help each participant draft one small experiment
  • use peer feedback to check scope, boundaries, and review criteria
  • close by connecting the structure to facilitation with colleagues

The participant resources for these steps are Sandbox Experiment and the Facilitation Guide.

Suggested Pacing

DurationRecommended usePractical note
30-45 minutesfirst meeting focused only on experiment discoveryuse the shorter-session guidance in Facilitation Guide
75 minutesfull sessionexplore a prepared sandbox, individual drafting, peer feedback, and facilitation handoff
90 minutesfirst implementation or varied participant backgroundsadd more time for individual drafting and table discussion
120+ minutesdepartment team or deeper planningadd more time for adaptation and reflection

Session Outcomes

Aim for participants to leave with:

  • a specific task or artifact they want to work on
  • a small experiment draft they could realistically try
  • the source material or context the AI would need
  • a clear statement of what stays educator judgment
  • one review criterion
  • one peer feedback note
  • one reason to continue, revise, or stop
  • one facilitation technique they could reuse with colleagues

Suggested Agenda (90 Minutes)

  • Part 1 (15 min): frame context engineering as preparing the task, materials, boundaries, and review criteria before using AI
  • Part 2 (25 min): explore a prepared sandbox in small groups
  • Part 3 (25 min): draft one low-stakes experiment for an individual context
  • Part 4 (15 min): exchange peer feedback
  • Part 5 (10 min): identify one next decision and one facilitation technique

Before You Run the Session

Decide these basics before you begin:

  • one prepared shared sandbox or demo you will use
  • how people will work in the room and what AI access they will have
  • one simple starter participants can adapt, such as the shared sandbox prompts, a short context template, or Set 2 from Workshop Prompts
  • what boundaries, cautions, or follow-up options you want to mention during the session

Room setup and tool access

Do not assume every participant has their own device, account, or AI tool.

  • individual work: each person has their own device and chat window
  • shared work: pairs or small groups share one device or one thread
  • limited access: the facilitator runs the tool on a shared screen and participants work from notes, discussion, and a few volunteer examples

Any chat-style AI tool can work for this workshop. What matters is seeing what changes when a vague ask becomes specific enough to judge.

Part 1: Show Why Context Matters

Frame the Session

Open with purpose:

  • this is not tool training
  • this is not a survey of everything AI can do
  • any chat-style AI tool can work for the workshop
  • we will work from one specific task in a course, support, or other work context
  • we will start with something small enough to try and learn from
  • the goal is to leave with a starting point they can use for one task

Introduce the simple model:

  • LLMs are good at filling in patterns
  • if your ask is vague, they fill in the gaps with generic assumptions
  • if you give a specific task, enough background, what you want the result to do, and any limits, the response is easier to judge
  • the educator still sets the standard and decides what to keep, revise, or reject

In this workshop, context means the details of your teaching or support situation that help you judge whether the response fits your situation.

  • the prompt is what you type
  • the context is the situation you bring with it

The core lesson is simple: set the context before you ask.

Concrete example: the same task with and without context

Vague ask: “Make me 5 quiz questions on cell transport.”

With context: “I teach Intro Biology. I need 5 short review questions for next week’s class on cell transport. My students often confuse diffusion, osmosis, and active transport. I want questions that reveal those misconceptions without being too difficult. Keep the language clear enough for first-year students. I will check scientific accuracy and whether the questions match what we covered in class.”

The prompt is the request for quiz questions. The context is the course, timing, student difficulty, desired level, and what the educator will review.

Demonstrate a Vague Ask and the Same Ask with Context

Use one facilitator prompt from Workshop Prompts, but do not begin with the full version. Start with a vague ask first, then improve it in front of the group.

Suggested sequence:

  1. show a short request tied to a teaching or support task
  2. ask the group what is missing
  3. add the task, the course or support-work context, what you want the result to do, any limits, and what you plan to check
  4. run the version with context
  5. compare the two responses briefly

Debrief with:

  • what changed once the context became more specific?
  • what still needed human review?
  • what would make this worth using in your practice?

Keep the demonstration short. The point is to make the contrast visible, not to impress people with the response.

Part 2: Explore, Draft, And Review

This part uses a group-to-individual structure.

Activity A: Sandbox Experiment (20-25 minutes)

Ask each table to use Sandbox Experiment. One person opens the prepared sandbox for the table and the group discusses what the designed context makes possible.

The table is looking for practical differences:

  • what the sandbox can do when the task and boundaries are already stated
  • what information it still asks educators to provide
  • where disciplinary or instructional judgment remains necessary
  • what review criteria make the work easier to judge

Bring the room back with two questions:

  1. What information did the sandbox need before it could help well?
  2. What stayed with the educator?

Activity B: Draft One Individual Experiment (20-25 minutes)

Ask participants to move from table discovery to their own context. They can use the exercise on Sandbox Experiment or the interactive planner.

Ask them to draft in brief notes:

  • task or artifact
  • course, learner group, support setting, or program context
  • learning goal or work goal
  • source material they can safely use
  • what AI may help with
  • what stays educator judgment
  • boundaries, academic integrity needs, or privacy limits
  • what they will look for

As you circulate, help participants narrow the task. If someone is trying to redesign a whole course, ask for the first activity, assignment step, feedback moment, or support interaction they could test.

By the end of this activity, each participant should have a draft experiment that is specific enough for peer feedback.

Activity C: Peer Feedback (10-15 minutes)

Use pairs or table groups. The reviewer is checking the experiment design, not approving the AI use.

Ask reviewers to check:

  • Is the task specific?
  • Is the scope small enough to try?
  • Is educator judgment visible?
  • Are student agency and academic integrity protected?
  • Is there a clear review criterion?
  • What should be answered before trying it?

Each participant should leave this activity with one practical revision.

Part 3: Pause, Review, and Look Ahead

Use A Brief Wrap-Up

Keep the close brief and focused. By this point, participants have already done the main thinking. Use this final part of the session to help them notice what seems worth keeping, what still needs review, and whether anything is worth continuing.

Choose the wrap-up format that fits the room:

  • if people have their own device or shared thread, ask them to stay in the same conversation and use a short AI-assisted wrap-up
  • if access or time is limited, do this as a spoken reflection and try to capture a few notes

Quick wrap-up prompt

Ask participants to send this as a follow-up message in the same AI conversation they just used. If they need to start a new chat, they should first paste in the AI request and response from their test. They should review and edit the summary before keeping it.

I just ran a small workshop test with AI. Based on the request and response in this conversation, help me make sense of it. In plain language, give me: 1. what seems most worth keeping here 2. what I would still need to check or revise 3. what this helped me understand about giving context 4. one possible next step if I want to keep going
Copy this follow-up message into the AI chat you just used, or into a new chat after pasting the request and response from the test.

If you are not using devices, ask the same questions out loud and invite people to jot notes.

Close with Shared Takeaways

Bring the room back together in a way that fits the setting. This can be a short spoken round, a few volunteers, a shared board, or a quick whole-group debrief.

Useful closing prompts:

  • what changed when more context was added?
  • what felt clearer or more worth keeping?
  • what still needs human judgment?
  • what would you want to try, adjust, or leave aside after this?

Participants do not need to answer all four. Use one or two if time is short.

End with a Simple Invitation

Close by summarizing what the group tried and what the optional next move could be. Help people leave with a sense of completion and a possible path forward.

You might say:

  • today was about seeing what changes when a vague ask becomes a more specific AI request
  • if you want to keep developing the example you started, go to Run an Experiment
  • if you want to browse the sandbox more broadly first, start at Welcome or the Interactive Planner

Choose one or two of these options based on the group. Do not try to walk everyone through every follow-up link in the final minutes.

If you want more structured feedback, send a short survey after the workshop rather than using the close for that.

Adaptation Notes

For department-specific runs, keep the structure and add more course, program, or departmental detail.

Use:

  • Adapting for Your Department
  • Case Study: Physics MCQ

The session works best when participants leave with an experiment they could realistically try, plus a shared way of talking about context, quality, limits, evidence, and revision.
